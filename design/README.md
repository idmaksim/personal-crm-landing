# Handoff: Лендинг «Круг» — персональная CRM

## Overview
Одностраничный маркетинговый лендинг для персональной CRM. Единственное целевое действие на всей странице — переход в приложение (кнопка **«Открыть CRM»**). Вторичное действие — ссылка **«Войти»**. Стиль — минимализм в духе Notion: тёплый off-white фон, спокойная типографика, золотисто-бежевые акценты.

Две версии макета:
- **mobile.dc.html** — мобильная вёрстка (дизайн-ширина 390px, одна колонка).
- **desktop.dc.html** — десктопная вёрстка (контент-контейнер 1160px, многоколоночные секции).

## Target stack
- **Astro** + **Tailwind CSS 4**, статическая страница (SSG, без клиентского JS — страница полностью статична).
- Одна страница (`src/pages/index.astro`). Переиспользуемые куски (карточка напоминания, пункт выгоды) можно вынести в `.astro`-компоненты, но это не обязательно.
- Внешнего JS не требуется: нет интерактива, только ссылки-CTA. Hover-состояния — чистый CSS/Tailwind.

## About the design files
Файлы `mobile.dc.html` и `desktop.dc.html` — **дизайн-референсы, собранные в HTML** (прототипы внешнего вида и поведения), а не продакшн-код для копирования. Задача — **воссоздать эти макеты на Astro + Tailwind 4**, используя токены и измерения ниже. Это один адаптивный лендинг: собрать его mobile-first, десктопные стили навесить на брейкпоинте.

Внутренняя структура исходников — это формат рантайма дизайн-компонентов (`<x-dc>`, `support.js`, инлайн-стили). Игнорируйте обвязку рантайма; берите разметку, тексты, цвета, размеры.

## Fidelity
**High-fidelity.** Финальные цвета, типографика, отступы и состояния. Воссоздавать pixel-perfect средствами Tailwind.

## Responsive behavior
Один брейкпоинт между мобильной и десктопной раскладкой.
- **Mobile** (дизайн-ширина **390px**): всё в одну колонку, контент внутри карточки-«телефона» со скруглением 28px на фоне #ECEBE8.
- **Desktop** (контент-контейнер **max-width 1160px**, по центру, фон #ECEBE8, паддинг страницы 28px): многоколоночные секции внутри белого контейнера со скруглением 28px.

Рекомендуемая точка переключения — **Tailwind `lg` (1024px)**: ниже — мобильная раскладка, от 1024px и выше — десктопная. (В брифе точка обозначена как *mobile → x / desktop → y*; если нужны конкретные значения, подставьте их в единственный брейкпоинт — вся логика адаптива держится на нём.)

Отличия десктопа от мобилки — только раскладка и размеры шрифтов; палитра, компоненты и копирайт идентичны.

### 6. Выгоды «Что это даёт»

1. **Входишь в разговор с готовым контекстом** — Помнишь о человеке всё важное
2. **Поддерживаешь связь со всеми, кто важен** — Напоминания держат отношения живыми
3. **Нужный человек находится за секунды** — Нетворкинг работает на тебя
4. **Вся база в одном месте** — Вместо десяти мессенджеров

Mobile: вертикальный список. Desktop: сетка 2×2, каждый пункт в карточке (`#FFFEFC`, рамка `#EDEAE4`, радиус 16px), фон секции `#FBFAF7`.

### 7. Финальный CTA
Бежевая плашка `#F7F3EA`. H2 **«Твои связи — твой капитал. Распоряжайся им с умом.»** + тёмная кнопка **«Открыть CRM»**. Mobile — выравнивание влево; desktop — по центру (H2 max-width 720px).

## Interactions & Behavior
- Страница статична. Все CTA («Открыть CRM») и «Войти» — обычные ссылки `<a href>`; целевые URL уточнить у заказчика (app-URL для «Открыть CRM», страница логина для «Войти»).
- Hover кнопок: лёгкое затемнение `#37352F` (напр. до `#2B2A25`) — на усмотрение, в макете не фиксировано; реализовать через `hover:` Tailwind.
- Подписи напоминаний: **одна строка**, перенос запрещён (`whitespace-nowrap overflow-hidden text-ellipsis`). Длинный текст обрезается многоточием.
- Эффекта hover у карточек нет.

## State management
Нет. Статическая страница без клиентского состояния и фетчинга. Контакты/напоминания — захардкоженный демо-контент в разметке.
